`lazy` holds back every script the named route doesn't load up front, then reloads the page. It reads the build's own manifests to find them, the same way `check:bundle` counts a route's first load, because SvelteKit names chunks by hash alone. Scenes run without a service worker, so this is what a plain-http LAN install or a stale tab after a deploy sees. By default each held request waits until a `release` step names the same route, as `palette-slow` does to type right after Ctrl K while the palette's results are still loading. With `fail: true` every such request fails instead, as `palette-down`, `sign-in-lazy-down` and `auth-down-lazy-down` do to show that the palette says so and that sign-in and "Can't reach Conveyor" never depend on a lazy chunk.
